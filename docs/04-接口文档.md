## 一、通用约定

### 1.1 BaseURL

| 环境 | BaseURL | 说明 |
| --- | --- | --- |
| 本地开发（经 Vite 代理） | `http://localhost:5173/api` | `vite.config.js` 中 `/api` → `http://127.0.0.1:8080` |
| 本地开发（直连后端） | `http://localhost:8080/api` | 后端 `server.port=8080` |
| Docker 生产（经 Nginx） | `http://localhost:8081/api` | `nginx.conf` 中 `/api/` → `http://backend:8080/api/` |

> 本文档中所有路径均以 `/api` 开头，完整 URL = BaseURL + 路径。

### 1.2 统一响应结构

所有接口（含异常）均返回 `Result<T>`：

```json
{ "code": 200, "message": "操作成功", "data": {}, "timestamp": 1760000000000 }
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | `Integer` | 业务状态码，**200 表示成功** |
| `message` | `String` | 提示信息（中文） |
| `data` | `T` | 业务数据，无数据时为 `null` |
| `timestamp` | `Long` | 服务端时间戳（毫秒） |

### 1.3 分页结构

分页接口的 `data` 为 `PageResult<T>`：

```json
{ "records": [], "total": 40, "page": 1, "size": 10, "pages": 4 }
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `records` | `Array` | 当前页数据 |
| `total` | `Long` | 总记录数 |
| `page` | `Long` | 当前页码，**从 1 开始** |
| `size` | `Long` | 每页条数 |
| `pages` | `Long` | 总页数 = `(total + size - 1) / size` |

**分页约束**：`page < 1` 归一到 1；`size < 1` 归一到 10；**`size > 200` 截断为 200**（分页插件 `setMaxLimit(200)` + Service 层 `Math.min(size, 200)` 双重限制）；`setOverflow(false)` 使**超出总页数返回空列表**而非回到首页。

### 1.4 状态码约定

| `code` | HTTP 状态码 | 含义 | 触发场景 |
| --- | :---: | --- | --- |
| `200` | 200 | 操作成功 | 正常返回 |
| `400` | 200 | 请求参数错误 | Bean Validation 失败、缺必填参数、请求体格式错误、方法不支持、文件过大 |
| `401` | **401** | 未登录或登录已过期，请重新登录 | 未带 Token 访问受保护接口；Token 过期/被踢/被顶替 |
| `403` | **403** | 抱歉，您没有该操作权限 | 权限不足；用户类型不匹配（如买家 Token 访问 `/api/admin/**`） |
| `404` | 200 | 请求的资源不存在 | `NoHandlerFoundException` |
| `500` | 200 | 系统繁忙，请稍后重试 | 未捕获异常 |
| `600` | 200 | 业务处理失败 | `BusinessException`（**最常用**），携带具体中文业务提示 |

**⚠️ 只有 401 与 403 会同时设置 HTTP 状态码**（`SecurityConfig.writeJson` 中的 `response.setStatus(...)`），其余错误 HTTP 状态码都是 200，仅 `code` 不同。前端拦截器对非 200 的 `code` 统一 `ElMessage.error(message)` 并 reject。

### 1.5 认证方式

**两种 Token，互不通用**：

| 端 | 登录接口 | 请求头 | 前端存储键 |
| --- | --- | --- | --- |
| 买家端 | `POST /api/auth/login` | `Authorization: Bearer <token>` | `mall_buyer_token` |
| 管理端 | `POST /api/admin/auth/login` | `Authorization: Bearer <token>` | `mall_admin_token` |

| 配置项 | 取值 |
| --- | --- |
| 请求头名 | `Authorization`（`mall.jwt.header`） |
| 前缀 | `Bearer `（含空格，`mall.jwt.prefix`） |
| 有效期 | **604800** 秒（7 天，`mall.jwt.expire`） |

**校验规则（`TokenService.getLoginUser`）**：① JWT 验签通过且未过期；② Redis 存在 `mall:login:{type}:{userId}`；③ Redis 中的 `token` 与请求 Token **完全一致**（否则说明该账号已在别处重新登录，当前 Token 被顶替）。

> **单一登录**：同一账号只有一个有效 Token，新设备登录会使旧 Token 立即失效。

**Token 立即失效的场景**：

| 场景 | 触发接口 |
| --- | --- |
| 买家 / 管理员退出登录 | `POST /api/auth/logout`、`POST /api/admin/auth/logout` |
| 会员被禁用 | `PUT /api/admin/users/{id}/status`（`status=0`） |
| 管理员被禁用 / 删除 | `PUT|DELETE /api/admin/sys/users/{id}` |
| 管理员角色变更 | `PUT /api/admin/sys/users/{id}`（`roleId` 变化） |
| 管理员密码被重置 | `PUT /api/admin/sys/users/{id}/password` |
| 角色权限重新分配 | `PUT /api/admin/sys/roles/{id}/permissions`（该角色下全部管理员下线） |

**不会失效的场景**：买家自行修改密码（`PUT /api/user/password`）；角色被停用（`PUT /api/admin/sys/roles/{id}/status`，**已知改进点**）。

### 1.6 公开接口（无需 Token）

`SecurityConfig.WHITE_LIST` 完全放行的路径：

```
/api/auth/**          买家注册、登录、退出、当前用户
/api/admin/auth/login 管理端登录
/api/shop/**          商城公开接口（分类/商品/评价/轮播图/公告/优惠券）
/api/files/**         图片静态资源
/api/common/**        公共接口（预留）
/doc.html  /webjars/**  /v3/api-docs/**  /swagger-ui/**  /swagger-ui.html  /favicon.ico  /error
```

此外 `OPTIONS /**` 全部放行（CORS 预检）。**其余接口**：`/api/admin/**` 需 `TYPE_ADMIN`；`/api/cart/**`、`/api/order/**`、`/api/address/**`、`/api/comment/**`、`/api/refund/**`、`/api/user/**` 需 `TYPE_BUYER`。

> `/api/auth/logout` 与 `/api/auth/me` 在白名单内，未带 Token 时不会返回 HTTP 401，而是进入业务后由 `SecurityUtils.getUserId()` 抛 401 业务码。

### 1.7 时间格式

| 场景 | 格式 | 示例 |
| --- | --- | --- |
| 响应时间字段 | `yyyy-MM-dd HH:mm:ss` | `"2026-10-13 14:30:00"` |
| 响应日期字段（生日） | `yyyy-MM-dd` | `"1995-06-15"` |
| 请求时间参数（订单/日志查询） | 支持 `yyyy-MM-dd`、`yyyy-MM-dd HH:mm`、`yyyy-MM-dd HH:mm:ss`、ISO `T` 分隔 | `"2026-10-01"`、`"2026-10-01 08:30"` |
| 请求时间参数（优惠券） | **仅** `yyyy-MM-dd HH:mm:ss` | `"2026-10-01 00:00:00"` |
| 请求生日（个人资料） | `yyyy-MM-dd` | `"1995-06-15"` |

**区间边界**：只传日期时，`startTime` → 当天 `00:00:00`，`endTime` → 当天 `23:59:59`。

**格式非法的行为差异**：订单查询**静默忽略**该条件（`log.warn`）；日志查询**明确报错** 600「时间格式不正确，应为 yyyy-MM-dd 或 yyyy-MM-dd HH:mm:ss」；优惠券保存**明确报错** 600「生效时间格式应为 yyyy-MM-dd HH:mm:ss」。

### 1.8 金额格式

JSON 中为**数值**（非字符串），固定 2 位小数，Java 侧 `BigDecimal`，数据库 `DECIMAL(10,2)`，范围 `0.00` ~ `99999999.99`。

**折扣率特殊语义**：`coupon.discount` 为 `DECIMAL(4,2)`，**`8.50` 表示 8.5 折**（付原价的 85%），合法区间 `0.10` ~ `9.90`，默认 `10.00`（等于不打折）。

### 1.9 其他约定

| 项 | 约定 |
| --- | --- |
| `Content-Type` | JSON 接口 `application/json`；文件上传 `multipart/form-data` |
| 字符编码 | UTF-8（`server.servlet.encoding.force=true`） |
| 逻辑删除 | 9 张含 `deleted` 字段的表，查询自动过滤 |
| 文件导出响应头 | `Content-Disposition: attachment; filename*=UTF-8''<URL编码文件名>` |
| CORS | 允许任意来源模式与全部方法/请求头，暴露 `Content-Disposition`，`allowCredentials=true`，预检缓存 3600 秒 |
| 请求体大小 | 单文件 ≤ 10MB，单请求 ≤ 50MB |
| DELETE 带请求体 | 部分接口（购物车批量删除、日志批量删除）需携带 JSON 数组 body |

### 1.10 双传参兼容说明

以下接口的状态参数**同时支持 URL 查询参数与 JSON 请求体**，都传时**查询参数优先**：

`PUT /api/admin/users/{id}/status`、`PUT /api/admin/sys/users/{id}/status`、`PUT /api/admin/sys/roles/{id}/status`、`PUT /api/admin/banners/{id}/status`、`PUT /api/admin/coupons/{id}/status`、`PUT /api/admin/comments/{id}/status`、`PUT /api/admin/notices/{id}/publish`

实现方式为 `@RequestParam(required = false) Integer status` + `@RequestBody(required = false) Map<String, Object> body`，由 Controller 内的 `resolveStatus` 兜底解析并抛出明确错误（「缺少状态参数」/「状态参数不合法」）。

## 七、订单

> 全部需 **`TYPE_BUYER`**。买家端用**订单号**（`orderNo`）定位，管理端用**数字ID**。

### 7.1 `POST /api/order/preview` 结算预览

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | :---: | --- |
| `cartIds` | `Array<Long>` | 二选一 | 购物车条目ID列表 |
| `buyNow` | `Object` | 二选一 | `{skuId, quantity}`（`skuId` 必填，`quantity` 最小 1） |
| `userCouponId` | `Long` | — | 用户优惠券ID（`user_coupon.id`） |

```json
// 请求
{ "cartIds": [1, 2], "userCouponId": 1 }
// 响应
{
  "code": 200, "message": "操作成功",
  "data": {
    "items": [
      { "productId": 1, "skuId": 1, "productName": "星辰 X9 Pro 5G 智能手机",
        "productImage": "/api/files/product/p1_1.svg", "specInfo": "曜石黑 / 12GB+256GB",
        "price": 3299.00, "quantity": 2, "totalAmount": 6598.00 }
    ],
    "address": { "id": 1, "receiver": "张三", "phone": "13800000001",
                 "fullAddress": "广东省深圳市南山区科技园路 1 号 A 座 1001", "isDefault": 1 },
    "totalAmount": 6598.00, "freightAmount": 0.00, "discountAmount": 50.00, "payAmount": 6548.00,
    "userCouponId": 1,
    "availableCoupons": [
      { "id": 1, "couponId": 1, "couponName": "新人专享 50 元券", "type": 1, "amount": 50.00,
        "discount": 10.00, "minAmount": 299.00, "status": 0, "statusName": "未使用",
        "expireTime": "2026-12-31 23:59:59", "description": "全场通用，满 299 元可用" }
    ]
  },
  "timestamp": 1760329200000
}
```

**金额规则（全部服务端重算，不信任前端）**：

| 公式 | 规则 |
| --- | --- |
| `totalAmount` | `Σ(sku.price × quantity)`，`setScale(2, HALF_UP)` |
| `freightAmount` | `totalAmount >= 99.00` → `0.00`，否则 `10.00` |
| `discountAmount` | 满减直减 `amount`；折扣 `total × (1 - discount/10)`，**上限 100.00**；且不超过 `totalAmount` |
| `payAmount` | `max(totalAmount + freightAmount - discountAmount, 0.01)` |

- `availableCoupons` 是**当前订单真正可用的券**（已按门槛、范围、有效期过滤）；传了不可用的券会返回 600 而非忽略；
- `address` 为默认地址，无地址时为 `null`；
- 本接口**只读，无副作用**。

**业务错误（600）**：同时传 `cartIds` 与 `buyNow` → 「请勿同时使用购物车结算与立即购买」；两者都空 → 「请选择要购买的商品」；购物车归属不符 → 「购物车记录不存在或无权操作」；商品下架 → 「商品「X」已下架」；SKU 停用 → 「商品「X」的该规格已停用」；库存不足 → 「库存不足：X（规格），当前仅剩 N 件」；券相关 → 「优惠券不存在或无权使用」/「该优惠券已使用或已过期」/「该优惠券已过期」/「该优惠券尚未生效」/「该优惠券已停用」/「订单金额未满 N 元，无法使用该优惠券」/「该优惠券不适用于本次购买的商品」。

### 7.2 `POST /api/order/submit` 提交订单

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | :---: | --- |
| `addressId` | `Long` | ✅ | 收货地址ID（必须属于本人） |
| `cartIds` | `Array<Long>` | 二选一 | 购物车条目ID列表 |
| `buyNow` | `Object` | 二选一 | `{skuId, quantity}` |
| `userCouponId` | `Long` | — | 用户优惠券ID |
| `remark` | `String` | — | 买家备注 ≤ 255 |

```json
// 请求
{ "addressId": 1, "cartIds": [1, 2], "userCouponId": 1, "remark": "请在工作日送达" }
// 响应
{ "code": 200, "message": "下单成功",
  "data": { "orderId": 41, "orderNo": "MO202610131430250001", "payAmount": 6548.00 },
  "timestamp": 1760329200000 }
```

- **单事务**：写订单 → 写明细 → 原子扣库存 → 核销券 → 清购物车，任一失败全部回滚；
- 订单号格式 `MO` + `yyyyMMddHHmmss` + 4 位随机数（共 20 字符），冲突最多重试 10 次；
- 新订单状态 **`0` 待付款**；收货信息与商品信息**快照**写入；
- 扣库存 SQL：`UPDATE product_sku SET stock = stock - q, sales = sales + q WHERE id = ? AND stock >= q`，影响 0 行即抛 600「库存不足：X」并整体回滚；
- **超时未支付自动取消**：默认 **30** 分钟（`mall.shop.order-auto-cancel-minutes`），在买家查询订单列表/计数时惰性触发。

**额外错误**：地址不存在或非本人 → 600「收货地址不存在或无权使用」；`addressId` 为空 → 400「请选择收货地址」。

### 13.3 `POST /api/admin/products` 新增商品

**权限**：`product:add` ｜ **@OperLog**：`module="商品管理", value="新增商品"`

**SPU 字段**：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | :---: | --- |
| `categoryId` | `Long` | ✅ | 分类ID |
| `name` | `String` | ✅ | 商品名称 ≤ 200 |
| `subtitle` / `brand` / `unit` | `String` | — | 副标题 ≤ 255 / 品牌 ≤ 50 / 单位 ≤ 20（**新增缺省「件」**） |
| `mainImage` | `String` | — | 主图URL ≤ 255 |
| `images` | `Array<String>` | — | 轮播图（拼接后总长 ≤ **2000**） |
| `detail` | `String` | — | 图文详情 HTML |
| `status` | `Integer` | — | 上架状态，新增缺省 **1** |
| `isRecommend` / `isNew` / `isHot` | `Integer` | — | 标记，缺省 **0** |
| `sort` | `Integer` | — | 排序值，缺省 **0** |
| `warnStock` | `Integer` | — | 预警阈值，缺省取配置（**10**） |
| `costPrice` | `BigDecimal` | — | 成本价，缺省 **0.00** |
| `specs` | `Array<Object>` | — | 规格定义数组 |
| `skus` | `Array<Object>` | ✅ | **至少 1 个** |

**`specs[]`（`SpecSaveDTO`）**：`specName`（✅ 必填）、`specValues`（`Array<String>`）、`id`（新增时忽略）。

**`skus[]`（`SkuSaveDTO`）**：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | :---: | --- |
| `price` | `BigDecimal` | ✅ | 售价 ≥ 0 |
| `stock` | `Integer` | ✅ | 库存 ≥ 0 |
| `id` | `Long` | — | 新增留空；编辑时传 ID 表示更新 |
| `skuCode` | `String` | — | 编码 ≤ 64 |
| `specData` | `String` | — | 规格 JSON 对象字符串，**≤ 500 字符** |
| `specInfo` | `String` | — | 展示文本；**为空时由 `specData` 的值以 `" / "` 拼接**，超 200 截断 |
| `originalPrice` | `BigDecimal` | — | 原价；**为空时取 `price`** |
| `image` | `String` | — | SKU 图URL |
| `status` | `Integer` | — | `1` 启用 / `0` 停用，缺省 **1** |

```json
// 请求
{
  "categoryId": 5, "name": "测试多规格商品", "subtitle": "用于接口测试", "brand": "测试品牌",
  "unit": "件", "mainImage": "/api/files/product/p1_1.svg", "images": ["/api/files/product/p1_1.svg"],
  "detail": "<p>商品详情</p>", "status": 1, "isRecommend": 0, "isNew": 1, "isHot": 0,
  "sort": 999, "warnStock": 10, "costPrice": 50.00,
  "specs": [ { "specName": "颜色", "specValues": ["红色", "蓝色"] },
             { "specName": "尺码", "specValues": ["M", "L"] } ],
  "skus": [
    { "skuCode": "AUTO-01", "specData": "{\"颜色\":\"红色\",\"尺码\":\"M\"}", "specInfo": "红色 / M",
      "price": 99.00, "originalPrice": 129.00, "stock": 30, "status": 1 },
    { "skuCode": "AUTO-02", "specData": "{\"颜色\":\"红色\",\"尺码\":\"L\"}", "specInfo": "红色 / L",
      "price": 109.00, "originalPrice": 139.00, "stock": 20, "status": 1 },
    { "skuCode": "AUTO-03", "specData": "{\"颜色\":\"蓝色\",\"尺码\":\"M\"}", "specInfo": "蓝色 / M",
      "price": 119.00, "originalPrice": 149.00, "stock": 10, "status": 1 }

{ "code": 200, "message": "新增成功", "data": 25, "timestamp": 1760329200000 }
```

- **SPU 派生字段自动计算**：`price = min(SKU 单价)`、`originalPrice = min(SKU 原价)`、`stock = Σ SKU 库存`、`sales = 0`；请求体中的这些 SPU 字段**会被忽略**；
- 接口**强制把 `id` 置为 null**；
- 规格采用**先删后插**策略。

**业务错误**：`categoryId` 空 → 400「请选择商品分类」；分类不存在 → 600「商品分类不存在」；`name` 空 → 400「商品名称不能为空」；`skus` 空 → 600「请至少添加一个 SKU」；`specData` 非法 JSON → 600「SKU 规格数据不是合法的 JSON 字符串：X」；`specData` 非对象 → 600「SKU 规格数据必须是 JSON 对象，如 {"颜色":"曜石黑"}」；超 500 → 600「SKU 规格数据长度不能超过 500 个字符」；图片总长超 2000 → 600「轮播图数量过多，地址总长度不能超过 2000 个字符」；标记非 0/1 → 600「X 只能是 0 或 1」。

### 13.4 `PUT /api/admin/products/{id}` 编辑商品

**权限**：`product:edit` ｜ **@OperLog**：`"商品管理" / "编辑商品"` ｜ **Body**：同 13.3

```json
// 请求（节选，注意 skus 带 id 表示更新、不带表示新增）
{
  "categoryId": 5, "name": "测试多规格商品（已编辑）", "unit": "件", "status": 1,
```

### 13.9 `GET /api/admin/products/template` 下载商品导入模板

**权限**：`product:import` ｜ **参数**：无 ｜ **响应**：Excel 二进制流，文件名 `商品导入模板.xlsx`

**模板表头（10 列）**：商品名称 / 副标题 / 品牌 / 分类名称 / 单位 / SKU规格(如 颜色:红色;尺码:M) / SKU价格 / SKU原价 / SKU库存 / SKU编码

**模板填写的 8 条说明（原文）**：

1. 同一商品名称填写多行，导入后自动合并为一个商品（SPU），每一行对应一个 SKU；
2. 商品名称为必填项，不能为空；
3. 分类名称必须与系统中已存在的商品分类名称完全一致，否则该商品导入失败；
4. 「SKU规格」格式为 `规格名:规格值`，多个规格之间使用英文分号(`;`)分隔，例如 `颜色:红色;尺码:M`；无规格商品可留空；
5. SKU价格、SKU原价、SKU库存必须填写数字，价格最多两位小数，库存为不小于 0 的整数；
6. SKU编码可留空；
7. 导入成功的商品默认为上架状态，单位为「件」（单位列留空时），不参与推荐、非新品、非热销；
8. 单行填写有误只影响该商品，其它商品仍会正常导入，错误明细随导入结果一起返回。

### 15.3 `PUT /api/admin/refunds/{id}/audit` 售后审核

**权限**：`refund:audit` ｜ **@OperLog**：`"售后管理" / "售后审核"`

| 参数名 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | :---: | --- |
| `id` | Path | `Long` | ✅ | 售后单ID |
| `status` | Body | `Integer` | ✅ | **`1` 同意 / `2` 拒绝 / `4` 退款完成**（**没有 3**） |
| `auditRemark` | Body | `String` | — | 审核意见 ≤ 255 |
| `refundAmount` | Body | `BigDecimal` | — | 覆盖退款金额（须 > 0 才生效） |

```json
// 同意（仅退款）
{ "status": 1, "auditRemark": "同意买家申请", "refundAmount": 6598.00 }
// 拒绝
{ "status": 2, "auditRemark": "商品已使用，不支持退款" }
// 退款完成
{ "status": 4, "auditRemark": "已收到退货，退款完成" }
// 响应
{ "code": 200, "message": "审核完成", "data": null, "timestamp": 1760329200000 }
```

**状态机校验规则**：

| `status` | 允许的当前售后状态 | 效果 |
| --- | --- | --- |
| `1` 同意 | 仅 `0` 待审核 | `type=1` 仅退款 → 直接置 `4` 退款完成并结算订单；`type=2/3` → 置 `3` 待买家退货 |
| `2` 拒绝 | `0` 或 `3` | 置 `2` 已拒绝；订单从 `5` 回退为 `3`（已收货）或 `2`（未收货） |
| `4` 退款完成 | `0`、`1` 或 `3` | 置 `4` + `finish_time`；**回补库存与销量**；结算订单 |

**订单结算规则**：`refundAmount >= orders.pay_amount` → 订单 **`4` 已取消**（写 `close_time`）；否则 → **`3` 已完成**（写 `finish_time`）。

**库存在不同分支的处理**：

| 分支 | 是否回补库存 |
| --- | :---: |
| `status=1` 同意 + `type=1` 仅退款 | ❌ **不回补**（商品未退回） |
| `status=1` 同意 + `type=2/3` | ❌ 不回补（等到"退款完成"） |
| `status=2` 拒绝 | ❌ 不回补 |
| `status=4` 退款完成 | ✅ **回补**（单品售后回补该明细，整单售后回补全部明细） |

**始终写入的审核信息**：`audit_user_id`、`audit_user`（登录管理员昵称/账号）、`audit_remark`、`audit_time`。

**业务错误（600）**：「审核结果不合法」/「仅待审核的售后单可以审核同意」/「当前售后状态不可拒绝」/「当前售后状态不可操作退款完成」/「售后单不存在」/「订单不存在」。参数校验（400）：「请选择审核结果」。

## 十九、状态码字典

### 19.1 订单状态（`orders.status`）

| 值 | 名称 | 说明 | 计入销售额 | 可申请售后 |
| :---: | --- | --- | :---: | :---: |
| `0` | 待付款 | 下单后的初始状态 | ❌ | ❌ |
| `1` | 待发货 | 已支付，等待管理员发货 | ✅ | ✅ |
| `2` | 待收货 | 已发货，等待买家确认收货 | ✅ | ✅ |
| `3` | 已完成 | 买家已确认收货，或退款额小于实付时的终态 | ✅ | ✅ |
| `4` | 已取消 | 买家取消 / 管理员关闭 / 超时未支付自动取消 / 全额退款 | ❌ | ❌ |
| `5` | 售后中 | 已提交售后申请，等待审核 | ✅ | ❌ |

`OrderStatus.descOf(code)` 未命中时返回「未知」。

### 19.2 售后状态（`refund.status`）与类型（`refund.type`）

| 状态值 | 名称 | 允许的后续操作 |
| :---: | --- | --- |
| `0` | 待审核 | 管理员同意(1) / 拒绝(2) / 退款完成(4)；买家撤销 |
| `1` | 已同意 | 管理员操作退款完成(4)。**当前代码路径下不会产生此状态** |
| `2` | 已拒绝 | 终态（订单状态已回退） |
| `3` | 待买家退货 | 管理员拒绝(2) / 退款完成(4) |
| `4` | 退款完成 | 终态 |
| `5` | 已撤销 | 终态（买家主动撤销，订单状态已回退） |

| 类型值 | 名称 | 审核同意后的走向 | 退款完成时回补库存 |
| :---: | --- | --- | :---: |
| `1` | 仅退款 | 直接置 `4` 退款完成 | ❌（同意时即完成，不回补） |
| `2` | 退货退款 | 置 `3` 待买家退货 | ✅ |
| `3` | 换货 | 置 `3` 待买家退货 | ✅ |

### 19.3 优惠券（`coupon.type` / `scope` / `status`）与用户券（`user_coupon.status`）

| 类型 | 名称 | 生效字段 | 计算方式 |
| :---: | --- | --- | --- |
| `1` | 满减 | `amount` | 直接减免 `amount` 元 |
| `2` | 折扣 | `discount` | 优惠额 = `商品总额 × (1 - discount/10)`，**上限 100.00 元** |

| 范围 | 名称 | 匹配规则 |
| :---: | --- | --- |
| `1` | 全场 | 始终可用 |
| `2` | 指定分类 | 命中商品的分类 **或** 其一级父分类即可用 |
| `3` | 指定商品 | 任一商品命中即可用 |

券状态 `coupon.status`：`1` 启用 / `0` 停用。
**折扣率 `discount`**：`8.50` 表示 **8.5 折**；合法区间 `0.10` ~ `9.90`；默认 `10.00`（不打折）。

用户券状态 `user_coupon.status`：

| 值 | 名称 | 说明 |
| :---: | --- | --- |
| `0` | 未使用 | 库值。若 `expire_time < now`，**响应中归一化为 `2`** |
| `1` | 已使用 | 已核销到某订单（`order_id` 非空） |
| `2` | 已过期 | 含库值即 2 的记录，以及"值为 0 但已过期"的记录 |

**取消订单后**：`status` 从 `1` 回到 `0`，`order_id` 与 `use_time` 置为 `NULL`。
